# DMC-600 APK 静态解包

分析对象是 FNIRSI+ APK 中的 ARM64 Dart AOT `lib/arm64-v8a/libapp.so`。SHA-256 为 `752b35b3b5501ea0ada42781803883e0ad9915b6ecd2cb08b7d0bbb13fb207e8`。本轮只读取 APK、ELF 和已有 Blutter 输出。下面的地址是这份 ELF 的虚拟地址。

表端固件分析见 [DMC-600 固件 V1.0.19](FIRMWARE_V1.0.19.md)。

## 设备配置与全部测量档

`CIn.dart` 的 `0x693798–0x6937b4` 把型号字符串 `DMC-600` 映射到设备配置类 `SS`。`wIn.dart` 的 `0x8ccccc–0x8ccd1c` 按设备名取得量程映射，再从字典键构建界面档位列表。`veo.dart` 的 `0xaf7b28` 可恢复与 DMC-600 相符的 14 项映射。构造函数在该地址创建 28 项键值数组，量程枚举用 `objs.txt` 解引用。与它相邻的 `0xaf8208` 是独立的 12 项映射，包含 `0x34` 智能 AUTO 档和 `0x35` 二极管/通断组合档。当前静态证据包含型号工厂和两张映射表，型号类到表地址之间还经过一次 AOT 动态分派。

| 码 | APP 枚举 | 功能 | 量程枚举 |
|---|---|---|---|
| `02` | `acVoltage` | 交流电压 | `pT` |
| `01` | `dcVoltage` | 直流电压 | `pT` |
| `06` | `acCurrent` | 交流钳形电流 | `bT` |
| `05` | `dcCurrent` | 直流钳形电流 | `bT` |
| `03` | `resistence` | 电阻 | `mT` |
| `04` | `capacitance` | 电容 | `YS` |
| `22` | `diode` | 二极管正向压降 | `cT` |
| `23` | `continuity` | 通断 | `aT` |
| `25` | `temperature` | 温度 | `oT` |
| `24` | `frequency` | 频率 | `bT` |
| `28` | `ncv` | 非接触电压检测 | `jT` |
| `29` | `live` | 单表笔火线检测 | `eT` |
| `2A` | `surge` | 浪涌电流 | `dT` |
| `2B` | `power` | 功率及电压、电流同测 | `dT` |

14 项全部只给 APP 提供一个可选量程 `AUTO (0x07)`。实时读数仍有自己的量程字段。通用 APP 的 `bT` 还包含 60 mA、600 mA 等其它量程，因此不能按其完整枚举把 DMC-600 返回的实时电流量程码翻成标签。APP 通用 `hT` 表共有 35 项，`BK` 表共有 19 个单位码。

## 状态、控制与设置

表中 ID 为原始属性值。Dart AOT 中的小整数可用两倍值表示，须结合调用现场区分。例如短整数 `0x200e` 对应属性 `0x1007`。

| 功能 | 属性 | 静态证据 |
|---|---|---|
| 档位与所选量程 | `0x1001` | `Kgo.dart:0x5284d0–0x5285a8` 解出 `mode` 和 `range`；ELF `0xc2365c` 构造该属性。 |
| 实时测量 | `0x1002` | `Kgo.dart:0x5285c0–0x528a50` 取主值、单位、显示后缀，以及第 2 和第 3 路读数。 `KHn.dart:0x53e174–0x53e340` 区分 `measureMode`、`runningMode`、`runningRange` 和 `measureRange` 对象字段。 |
| REL/ZERO 参考读数 | `0x1003` | ELF `0xc229a0` 匹配属性并走专门处理；`GAn.dart:0x68dcb4–0x68de28` 读取参考值和单位，`0x68d864` 与 `0x68d970` 把 REL/ZERO 标签和它用在同一个界面组件。 |
| HOLD | `0x1005` | `Kgo.dart:0x528a58–0x528ab8` 映射到 `hold`；`XIn.dart:0x8ccd88` 调用 ELF `0xc9d494`，其中 `0xc9d56c` 构造该写入属性。 |
| REL/ZERO 开关 | `0x1007` | `Kgo.dart:0x528ac8–0x528b34` 映射到 `rel`；`WIn.dart:0xc4c100–0xc4c10c` 翻转状态后调用 ELF `0xc4c1a0`，其中 `0xc4c278` 构造该写入属性。 |
| 屏幕亮度 | `0x0014` | `Kgo.dart:0x528384–0x5283e8` 映射到 `brightness`；设备设置路径见 `iJn.dart:0x837b98`。 |
| 音量 | `0x0015` | `Kgo.dart:0x5283f8–0x52844c` 映射到 `volume`；设备设置路径见 `iJn.dart:0x837ab4`。 |
| 设备语言 | `0x0017` | `Kgo.dart:0x52845c–0x5284c0` 映射到 `lang`；`iJn.dart:0x74a860` 使用该属性。 |
| 自动关机时长 | `0x0019` | `xIn.dart:0x74a098` 读取该属性；`iJn.dart:0x7489dc` 与 `qIn.dart:0x72df80` 对应设置标题。APP 有从不、5、15、30 分钟这一组值，`veo.dart:0xafa378` 返回 `FF 05 0F 1E`。相邻机型还有另一组时长。 |

原有规格把 `0x1003` 描述为用途未知。本轮从消费它的代码确定了 REL/ZERO 参考值的用途。对象字段名来自 APP 的属性映射，原始测量前四字节逐位对应关系仍以已确认的字段为准。

`0x0016`、`0x1006` 和 `0x1008` 在 ELF 查询构造器中出现，可分别从 `0xc2d5ec`、`0xc2d610`、`0xc2d778` 复查。另找到 `0x1006` 构造路径 `0xc42dcc`。这些位置能证明属性存在，界面用途仍待解析。`0x1010` 只找到通用比较指令 `0xbedb80`，尚不能归到 DMC-600 功能。

## APP 与表端功能的边界

- **Min/Max** 在 APP 有完整的本地实现。`wIn.dart:0x8ccb70–0x8ccba8` 用负无穷和正无穷初始化极值。 `XIn.dart:0x533da0–0x533fe4` 将单位换算后逐点比较并更新。 `GAn.dart:0x68ed98` 和 `0x68f014` 读取这两个结果。APP 因此可直接用普通测量流生成极值。
- **曲线与全屏** 走 APP 页面和图表控件。 `JAn.dart:0x699ad8` 和 `0x69ac4c` 有全屏入口，这些地址能确认 APP 图表的界面入口。仪表屏幕内部的采样率、缓冲和波形存档属于另一个实现，当前 APK 证据不足以复原。
- **录制、回看与导出** 由 APP 提供。万用表页离开时的录制提示位于 `UIn.dart:0x736f5c`，录制间隔与点数位于 `sJn.dart:0x751704` 和 `0x751d64`，录制列表的 CSV 导出入口位于 `VHn.dart:0x7124f8`。
- **NCV/LIVE** 的两个模式及各自 AUTO 范围枚举可从 APK 恢复。各档状态码对应的物理电压门限需要仪表固件或对应资料。
- **浪涌和同测功率** 在 APP 各有独立模式码。APP 消费仪表返回的数据，浪涌捕获窗口与功率计算公式尚无表端固件证据。
- **手电筒、表端波形文件和 USB 升级** 的仪表内部实现无法从这份手机 APK 完整恢复。当前项目只有 APP 的 AOT、Flutter 引擎和 APP 资源。

## 离线复现

在项目目录执行 `python tools/extract_function_profile.py`。它直接从 Blutter 压缩包导出 14 档配置、相邻机型配置、35 项通用档位枚举和 19 个单位码，输出 JSON。定位表所用地址与当前版本绑定。报告中的其余地址可在压缩包里的相应反汇编文件或 APK 提取的 ARM64 ELF 中核对。
